# Обмен с Blender и 3ds Max

Предпочтительный формат — FBX: геометрия, имена, иерархия и pivot находятся в одном файле. Поддерживаются статические и жёсткие детали. Skinning и произвольные анимационные дорожки FBX в этом обмене пока не поддерживаются. Нативный экспорт транспорта NMF/NAF остаётся отдельной командой.

OBJ не хранит иерархию, dummy и pivot. Aurora сохраняет рядом `model.obj.aur-scene.json`. Обычный импорт OBJ во внешнем редакторе прочитает только геометрию. Для обмена с pivot используйте комплект скриптов из этой папки и храните OBJ/MTL/JSON вместе:

- Blender: выполните `blender_aurora.py` в Text Editor. Через F3 вызовите `Aurora OBJ import` или `Aurora OBJ export`. Экспортируются импортированные Aurora-объекты и выделенные дополнительные объекты.
- 3ds Max: выполните `max_aurora.py` через Python scripting. Вопрос предлагает импорт, «Нет» — экспорт выделенных объектов; без выделения экспортируются ранее импортированные Aurora-объекты.
- `scene_io.py` должен лежать рядом с обоими скриптами.

Скрипты переводят игровые метры/Y-up в Z-up внешнего редактора. В 3ds Max учитываются текущие системные единицы. После редактирования используйте именно Aurora OBJ export, чтобы обновить pivot-файл. Для обычного FBX используйте штатные команды внешнего редактора, сохраняя имена и пустые узлы.

`Aurora_MainPivot` и `Aurora_Point_*` — служебные dummy для основного pivot и световых/дымовых точек. Их имена нужны для обратного восстановления настроек. Произвольные dummy сохраняются с исходными именами.

Автоматически проверены FBX/OBJ roundtrip, координаты, повёрнутые pivot, масштаб, иерархия, материалы и Unicode-пути. Интерактивная совместимость конкретных версий Blender/3ds Max требует проверки в этих программах: они не установлены на машине сборки. Скрипты поставляются с проверенным синтаксисом Python, но без заявления о live-проверке в DCC.
