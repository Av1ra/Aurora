# Решения владельца из доступной переписки

Это тематическая реконструкция требований, а не дословная стенограмма. При конфликте действует более позднее прямое указание. Наличие требования не означает завершение реализации: сверять [состояние](01_CURRENT_STATE.md), [ограничения](09_GAPS_AND_ROADMAP.md) и исходники.

## Основа продукта

- Нативный WinUI, версия 0.2. Один комплект Launcher + Editor, общий runtime, соседний маленький Setup без встроенной копии ZIP. Отдельного выпуска без запроса владельца не делать.
- Главная задача Editor — с нуля превратить OBJ в пригодный игровой транспорт, настроить все семь семейств транспорта и экспортировать переносимый мод. Донорская машина не должна быть обязательна.
- Сохранять оригинальные файлы игры; модульные overrides, резервные копии, квитанции и откат. Не считать сборку доказательством принятия транспорта игрой.
- Работать экономно, связанными исправлениями по 2–3 пункта; короткий отчёт. Ручные GUI/игровые проверки проводит владелец. Не вводить таймеры/автоматизации и не отвлекать активную игру.
- Архитектура, безопасность, масштабирование, отказоустойчивость — обязательные свойства; ошибки не должны молча уводить в другое окно.

## Launcher и модули

PSD содержит дизайн Launcher, который раньше был пропущен. FOV и консоль — компактные строки с переключателем и «Альфа». F9 — меню модуля в игре, tilde — консоль. Пользователь просил применение FOV сразу в игре; **нынешний FovChanger читает настройку при старте, это открытая задача**.

Исполняемый payload Editor в `app/Editor`, подписанные описания модулей в `mods`, graphics DLL в игровом `mods` — разные сущности. LogoAE встроен в исполняемые ресурсы; сохранять брендинг при сборке. Сам факт общего WinUI host не должен менять окно запуска Editor на Launcher.

## Материалы, модели, сохранение

1. Отдельный импорт текстур из главного меню отменён: назначение находится в материалах.
2. Стандартный material и PBR разделены. Две отдельные загрузки MTL внутри «Настройки материала», прежнее «Настройки PBR» переименовано. Убрать технический `pbr.mtl` из заголовка меню и нижней информации.
3. При открытии NMF/OBJ подтягивать реальные текстуры из соответствующих MTL и относительных путей; отображаемая модель и поля материала должны соответствовать друг другу.
4. Создавать материалы с нуля; поддерживать несколько материалов и варианты. Сохранять выбранные варианты и их зависимости переносимо. Пары `material.mtl`/`material_pbr.mtl`, `material_1.mtl`/`material_pbr_1.mtl` определяются renderer по native material identity.
5. «Сохранить NMF» открывает единое окно экспорта с выбором материалов. «Сохранить проект» создаёт единый .aur. Пароль не спрашивать. Встроенный ключ не означает, что никто, кроме Editor, технически не сможет прочитать файл.
6. Объекты, выбор и компоненты объединять под «Выбрать объект», не дублировать в Scripts. Нужны разделение несвязанных мешей и переименование вручную/штатными названиями колёс без длинных пояснений к каждому имени.
7. LOD принимает OBJ и NMF; добавление через +, выбор модели и дальность, замена и удаление. Не дублировать LOD в механизмах. В главном меню — полигональная сетка.

## Pivot, груз, механизмы

- «Починить ориентацию» исправляет pivot/разворот модели, не нормали. В viewport цветные оси, Move/Rotate, числовые поля и подтверждение. Centre ставит высоту по нижней точке модели.
- Главный pivot центрирует плоскости отражения точек. Фары/фонари — игровые координаты, направление задаёт основной pivot; отдельное произвольное вращение света не нужно. Четыре понятных назначения передний/задний левый/правый, возможность отражения по выбранной оси.
- Настройка груза визуальная: Move, Rotate, Scale, масштаб равномерный и по отдельным осям. Справа кнопки подходящих грузов. Груз следует за кузовом; при выборе ресурса обновляется груз, а не весь автомобиль.
- Undo/Redo Ctrl+Z/Ctrl+Y, отмена незавершённого действия и возврат pivot к сохранению. Ранее просились сотые, позднее точность всех обычных настроек ограничена десятыми. Стрелки числовых полей убрать везде.
- «Сборка и механизм» → «Механизмы». Понятные типы штатных действий, визуальный выбор модели и перемещение/вращение оси. Шаги 0,1; 0,5; 1; 10; 45; 90 или своё значение.
- Позднее **анимации явно разрешены**, старое откладывание отменено. Нужен timeline с ключами, FPS, интерполяцией и сглаживанием. Движение между кадрами постепенное. Анимации и механизмы объединить. Экспортировать **штатные действия транспорта**, произвольные условия запуска не запрошены.

## Скрипты и транспорт

- Model → «Скрипты» (Scripts по-английски). Не выводить пользователю необъяснённый сырой список ключей script.ini.
- Порядок основного сценария: блок → страна словами, с правильным соответствием блоку → годы 1900–2100 с начальной областью 1950–1960 → цена → остальные параметры класса/роли.
- Только применимые параметры данного класса. Максимальный объём непосредственно под грузом; «Настроить груз» рядом и только для подходящего транспорта. Грузы должны соответствовать типу кузова/роли.
- Звуки группировать по классам с приоритетом текущего; свои звуки — **только готовый INI**, не отдельная загрузка WAV. Не дублировать настройки звука и звуковые слои.
- Дым настраивать визуальными точками как свет, корректно учитывать принадлежность присоединённой части. Конная тяга и авиационные характеристики не должны появляться у обычного грузовика без причины.
- «Варианты покупки» и «Конструкция транспорта» непонятны. Последний проход переименовал FAMILY/PURCHASE_EXCLUDE в «Доступность и базовая модель», остальные элементы распределил по назначению. Не путать числовое значение/роль с произвольно выдуманным параметром игры.
- Для спорных расхода топлива, срока службы, мощности лошади и влияния уклона нужны доказательства штатным script.ini и семантикой. Срок службы/расход не возвращать как универсальные поля без подтверждения. Сам факт ключа не доказывает его единицы и действие.
- Читать файл без потери неизвестных секций/комментариев, не нормализовать всё по ограниченной форме интерфейса.

## Превью и эффекты

- Два штатных ракурса, ориентир FOV 20; настраивать в основном viewport. WASD — перемещение, QE — высота, ZX — крен, R — сброс, мышь — поворот, колесо — целочисленный FOV 5–120. Камера плавная.
- Shot сохраняет параметры камеры, а не немедленные файлы. При сохранении транспорта создавать качественные изображения для каждого варианта материалов с теми же камерами.
- Ночной режим — проверка настроенных игровых фар/фонарей. Не затемнять всю модель; использовать штатные игровые спрайты, визуальный размер увеличить по сравнению с первым маленьким вариантом.
- Маленькая кнопка солнца/луны показывает выбранный режим. Рядом левый и правый поворотники, маяки, тест колёс. Выключенный поворотник не мигает, включённый мигает.
- Пожарная струя **не относится к фарам**. Последним указанием тест струи убран. WATER_POINT остаётся настройкой эффекта, где применим. Автоматическое игровое наведение сопла не завершено.
- Проверка колёс должна использовать собственные центры и штатные оси; случайно не захватывать несколько колёс. По умолчанию выбранное колесо, все — явно.

## Одобренное на будущее и исключения

Владелец одобрял проверки перед экспортом, дерево объектов, сравнение native/PBR, просмотр LOD по расстоянию, проверку колёс, автосохранение, историю действий, drag-and-drop и другие рабочие инструменты. Часть есть частично, часть остаётся backlog: [следующие задачи](09_GAPS_AND_ROADMAP.md) и исторические требования в docs. Не выдавать одобрение списка за завершённую реализацию.

**Блокировка точек исключена.** Плагин переноса UI-макетов, PBR Workshop, песочница/особая карта внутри игры и дальнейшие идеи Launcher отложены; их нельзя начинать только из старых рассуждений. На обсуждение sandbox не отвечать утверждением, что обязательно нужна декомпиляция: сначала исследовать официальные способы загрузки карты/сохранения.

Текущая задача — перенос и анализ проекта, не автоматическое возобновление всех изменений интерфейса. Перед новым циклом согласовать его конкретный предмет уже на новом месте.
