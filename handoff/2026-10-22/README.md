## Быстрый перенос

```powershell
git lfs install
git clone https://github.com/Av1ra/Aurora.git
cd Aurora
git lfs pull
Get-Content handoff/2026-10-22/README.md
```

Git LFS нужен только для большого готового ZIP в этой папке; исходники, документация, PSD и Setup хранятся обычными Git-файлами. Если ZIP весит примерно 130 байт и начинается с `version https://git-lfs`, скачан указатель: выполнить `git lfs pull`.

Для исходников графики требуется доступ владельца к `https://github.com/Av1ra/GameData`. Не переносите закрытые renderer sources в другой публичный репозиторий автоматически. [Restore-Workspace.ps1](scripts/Restore-Workspace.ps1) создаёт отдельные checkout точных зафиксированных исходников; `-DryRun` выводит план без клонирования.

Для разработки достаточно `./build.ps1 -Development`. Временный ключ такой сборки отличается от production. Для выпуска под прежним издателем нужен существующий закрытый ключ, передаваемый защищённым способом отдельно. В GitHub его нет.

Локальная резервная передача: `C:\Users\AVR\Downloads\RESAURO.zip` и соседний `.sha256`. Внутри исходники, настоящие bytes пакета LFS, история Aurora main, приватная PBR-подсистема и инструкции восстановления. Создание: [Build-Resauro.py](scripts/Build-Resauro.py) с `--graphics <clone GameData> --output <Downloads/RESAURO.zip>`. Проверка handoff: [Verify-Handoff.py](scripts/Verify-Handoff.py). Этот архив не публикуется автоматически.

## Как понимать достоверность

- **Есть код** — функция найдена в исходниках.
- **Проверено автоматически** — указан воспроизводимый тест или проверка файлов.
- **Установлено** — файлы на ПК сверены с конкретной сборкой.
- **Проверено владельцем в GUI/игре** — отдельный результат, не выводится из PASS сборки.

Последний этап прошёл создание настоящего скрытого WinUI-окна, проверку панели/стиля и установку 572 файлов. Это **не** подтверждение всех интерактивных сценариев и не приёмка транспорта игрой.

Этот пакет — систематизация доступной переписки и проверенных файлов, а не побайтовый экспорт всех сообщений чата. Исторические Markdown часто содержат устаревшие «текущие» статусы; дата и описание ниже имеют приоритет для этого снимка.
