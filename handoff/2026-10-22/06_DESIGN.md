# Дизайн и поведение интерфейса

Приоритет решений: последнее прямое указание владельца → его PSD, включая скрытые слои → [каноническая политика GameData](https://github.com/Av1ra/GameData/blob/ce684080d356f5d729bb9c45a79df152ac54c89c/WORKFLOW/UI_DESIGN.md) → наблюдаемая реализация. Последняя показывает фактическое состояние, но не отменяет пожеланий. [Архив политики](assets/UI_DESIGN_REFERENCE.md) сохранён для автономного чтения; это не второй редактируемый стандарт.

## Визуальная система

Нативный WinUI, строгая компактная компоновка, большая рабочая область модели. Без неона, бессмысленных градиентов и множества карточек. Главное меню, «Выбрать объект», «Модификаторы», «Материалы», «Скрипты» находятся сверху. Объекты не должны дублироваться в Scripts. Нижний левый угол предназначен для маленьких кнопок проверки эффектов. Нижняя область не должна превращаться в постоянную инструкцию по управлению.

Mica оболочки и прозрачность меню — разные вещи: всплывающие меню, панели и кнопки должны иметь читаемый непрозрачный фон поверх яркой модели. Тема должна поддерживать высокий контраст. Не возвращать null Setter для `MenuFlyoutPresenter.SystemBackdropProperty`: он уже приводил к исключению конструктора. Проверка реального окна добавлена именно после этого сбоя.

Числовые поля без стрелок увеличения/уменьшения. Последнее требование владельца: обычные отображаемые значения до десятых; FOV — целое число 5–120. Это формат отображения, а не разрешение округлять неизменённые исходные данные при чтении/сохранении. Имена мешей, ключи формата и пути не переводить. Пользовательские подписи переводить полностью, включая вложенные окна и кнопки.

## PSD как источник

[Оригинал](assets/owner-ui.psd), [композит](assets/user-menu-psd.png), [инвентаризация 123 слоёв](assets/psd-layers.json). Размер исходника 3911×1870. Есть скрытые состояния меню и блоки «До/После». Смотреть только композит недостаточно.

В Launcher FOV и консоль должны выглядеть компактными строками: название слева, переключатель справа, отдельная отметка «Альфа». Отдельные строки «Включить» и большой ползунок из старого состояния не являются целевым дизайном. Не заполнять свободное место фиктивными функциями.

Старые версии и команды в PSD не актуализируют продукт автоматически: версия остаётся 0.2; отдельный «Импорт текстур» позднее отменён, поскольку назначение есть в материалах. Слой с названием Aurora Launcher внутри примера Editor сам по себе не означает переименование редактора. Поздние решения по камерам, механизмам и эффектам описаны в [решениях из чата](08_DECISIONS_FROM_CHAT.md).

## Реальные компоненты и размеры

Это ориентиры текущего кода, а не завершённая библиотека токенов:

| Элемент | Реализация / ориентир |
| --- | --- |
| Окно Editor | около 1250×850 логических единиц, подгонка к рабочей области и DPI |
| Верхняя полоса | горизонтальный StackPanel, шаг 6, отступы порядка 12/6; ScrollViewer обязательно добавлен в корневой Grid |
| Обычная кнопка | минимальная высота около 30, компактные отступы 10/3 |
| Меню | явный непрозрачный SolidColorBrush: тёмная тема около RGB 40, светлая около 249 |
| Viewport | спокойный фон около #202020; дневной режим не затемнять ради теста фар |
| Диалоги | обычно 420–500 логических единиц; содержимое вписывается в доступную ширину |
| Тест эффектов | маленькие кнопки порядка 34×32, состояние связано с IsChecked |
| Ошибки | InfoBar/контекстная ошибка; никаких незаметных переключений Editor → Launcher |
| Gizmo | XYZ разными цветами; Move/Rotate, для груза также Scale с общей и раздельными осями |

Фиксировать ширину дочерних полей с учётом scrollbar и padding. Ранее правая граница полей выходила за панель. В узком окне должна работать прокрутка, а не обрезание кнопок.

## Состояния и взаимодействие

- Меню открывается под кнопкой, если там достаточно места; учитывать границы окна. Предыдущие постоянные раскрытия вверх были дефектом.
- Ожидание выбора меша пользователем не равно фоновой загрузке. Нельзя отключать viewport, пока пользователь должен нажать на модель. Именно это вызывало бесконечную «загрузку анимаций».
- Редактирование положения/оси происходит в viewport. Выбор модели подтверждается кнопками «Выбрать» и «Отмена». XYZ нельзя возвращать в отдельное окно механизмов вместо визуального инструмента.
- Отмена восстанавливает черновик, Reset возвращает сохранённое состояние; undo/redo — Ctrl+Z/Ctrl+Y. Проверять все три пути отдельно.
- Поворотники имеют левую/правую кнопку. Положительный native X соответствует левой стороне на проверенных штатных моделях. Нажатие включает мигание, выключение прекращает его.
- Переключение груза и кадра анимации изменяет нужный объект/трансформ, не пересоздаёт автомобиль целиком.
- Пререквизит JOINT объясняется и должен быть исправим через выбор модели. Общая ошибка «выберите модель» без доступного выбора недопустима.
- Две камеры превью настраиваются в основном viewport. Shot запоминает настройки; экспорт делает изображения для каждого варианта материала.

## Что проверять после UI-изменения

Обычное и узкое окно; RU и EN; DPI 125–200%; фокус клавиатуры и Escape; непрозрачность меню поверх светлой геометрии; переключатель off/on/off; «Выбрать/Отмена», Reset и Undo; восстановление панелей после выхода из инструмента. Отдельно проверить запуск настоящего Editor через корневой EXE и из Launcher.

Автоматическая проверка конструктора не подтверждает эти интерактивные сценарии. Полной Figma-библиотеки, формальной системы всех токенов и завершённого визуального тестирования в этом снимке нет.
