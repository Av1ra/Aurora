Owner corrections replace automatic script-field forms. Keep WinUI, version 0.2, shared package, no release publication and no desktop/game automation. Owner tests real UI/game.

## Corrections

- Country blocs now use an explicit ID classification, not observed native vehicle purchase currency. That currency had incorrectly admitted western countries into the socialist list and vice versa. Opening an existing model initializes the bloc from its country. Native names remain localized BTF entries.
- Sound selection has two levels: class then deduplicated presets within that class. It starts at the model's class and preserves current sound settings until a preset is chosen. Owner explicitly chose **INI import only**, not WAV creation/registration. Imported native TEXT/FLOAT sound INIs are frozen in editor session files, copied into model exports with relative references and embedded/remapped inside portable .aur projects.
- Remove automatic unknown/all-directive editing, General, native description/family lists and bare mechanism coordinates from the settings form. Preserve those script records untouched. Show named, directly useful movement fields, class skill values, and cargo settings. This reverses the previous interpretation that every native header should become a UI field.
- Cargo choice, Configure cargo and maximum capacity are one adjacent block. Configure enters visual editing immediately rather than opening another selection dialog. A right-side palette exposes resource names plus area selection/add/remove. Switching resources preserves the camera and layout.
- Actual cargo failure: resource models commonly use *_vehicle.nmf with a base-name .mtl, and numbered waste models share an unnumbered material. Binary material names can also differ from MTL submaterial names. ResourceMaterial resolves the native aliases; ResourceMaps uses exact names when possible, otherwise the validated material order. Tests now parse every offered native resource AND resolve its textures/material binding, replacing the insufficient file-existence-only check.
- Movement exhaust is a native particle point edited with the positional XYZ gizmo, like lamps. Effect IDs/other emitters and lamps are preserved. Smoke tool selection participates in undo. This positions the actual native effect; it does not simulate particle rendering in the editor.
- LOD section uses + and two controls per row: model picker and distance. New NMFs are parsed before apply; models/script/distance changes share the undo transaction. Existing unresolved LOD references block apply instead of disappearing. Unrelated joint LOD directives are preserved. Model files must have distinct exported basenames.
- Pivot/lamp/cargo/exhaust coordinates display two decimals through a NumberBox formatter/rounder. Native geometry and stored source coordinates are not rounded just for display.

## Scripts, preview cameras and night inspection

Toolbar Model is now Scripts / Скрипты. Preview displays high-resolution 1024x1024 and 1024x512 inspection images. Shot stores the two shared camera poses in document/undo state and enables automatic preview export; it does not ask for a folder or write image files. Save project persists the camera configuration in .aur. Save NMF generates game-size 256x256 and 256x128 DDS files for every selected material variant, using the same camera settings. Camera editing now uses the full main viewport with a framing guide and a compact native controls panel with collapsible help. WASD moves, QE changes height, ZX rolls, R restores the standard view, mouse drag rotates, and wheel changes integer FOV from 5 through 120. Physical key codes also work with a Russian keyboard layout. Apply records camera pose in undo and .aur state; Cancel restores the original viewport. The framing guide preserves the final image aspect without shrinking the main viewport. Held-key movement, mouse orbit and wheel FOV use frame-rate-independent damping; key release/blur stop movement, and leaving camera editing cancels stale animation callbacks. UI numbers display at most one decimal; native unedited geometry/script precision is retained.

Bottom-left moon/sun switches editor day/night without changing the model or game settings. Lamp inspection keeps normal model illumination unchanged. It loads carlight_forward.dds/carlight_backward.dds from the installed game at runtime; no game artwork is bundled. A depth-tested additive sprite pass replaces the synthetic 2D gradient circles. Camera position relative to the main-pivot lamp direction controls sprite visibility; rear lamps no longer always draw on top of the body. This is an approximation of game lamp display, not a copy of the game renderer. Preview captures and camera editing use day lighting, then restore the editor view. This is editor inspection, not proof of identical game rendering.

Scripts settings first separate road, locomotive, wagon, ship, airplane and helicopter types, then show compatible classes. Native per-class field profiles prevent unrelated numeric settings from appearing. Optional consumption/service-life/takeoff fields appear only when present and applicable; service life no longer claims an unverified unit. Unknown script sections remain preserved. Parsing accepts BOM/lowercase headers, comments outside quoted strings, supported next-line scalar arguments and repeated fields; the first active end terminates parsing while its inactive tail remains untouched. Lamp read/write and supported pivot transforms share this parsing behavior. Unsupported active spatial sections still reject partial pivot transformation.

Automated evidence: core regression tests with bus_ikr_66 and the installed native catalog, WinUI builds, actual viewport-script tests for camera input/roll/reset/FOV limits/pose restoration and native-artwork sprite rendering, high-resolution inspection and game-size output.
