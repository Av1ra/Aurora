# Собственные объекты в одном проекте

21 октября 2026. Продолжать автономно до согласованного результата, не останавливаться после промежуточного комплекта. WinUI, версия 0.2. Внешние анимации и ранее отложенные идеи остаются вне текущей реализации.

## Реализовано в исходниках

- «Скрипты → Объекты комплекта»: добавить OBJ/NMF или отдельный проект, открыть другой объект, переименовать и удалить свободный объект. Каждый имеет собственные модели/LOD, варианты материалов, скрипт, груз, pivot и камеры. Настройка возможна с нуля через OBJ. Ссылки собственных секций в FAMILY/TRAINSET используют внутренний идентификатор aurora:имя; при игровом экспорте он обязательно заменяется на настоящий Workshop ID/объект.
- Один зашифрованный `.aur` содержит несколько самостоятельных документов. Общие данные хранятся по SHA-256 один раз. Сохраняются прежние пределы архива 256 MiB/2048 записей и не более 64 объектов. Старый однообъектный `.aur` открывается без преобразования владельцем. Добавление чужого однообъектного проекта меняет его ссылки на самого себя на новое локальное имя. Импорт всего другого многообъектного проекта пока отклоняется явно.
- Чтение/проверка документа вынесены из WinUI в `ProjectDocument.cs` и проверяются без окна. Оригинальный идентификатор native-объекта сохраняется отдельно. Нечитаемый дополнительный LOD можно оставить непрозрачной зависимостью проекта для дальнейшей замены; игровой экспорт по-прежнему требует корректного LOD и не выдаёт непреобразованные данные за исправленные.
- Экспорт комплекта обрабатывает все собственные объекты, их варианты материалов и настройки превью без переключения редактируемого документа. Отдельные модели, обычные/PBR-материалы, карты, звуковые INI и связанные модели переносятся в свои папки. Проверка камеры восстанавливает исходный вид после генерации изображений. Одиночный экспорт с оставшейся внутренней ссылкой проекта отклоняется.
- Переименование/удаление объекта включено в снимок истории активного документа; ссылки меняются вместе с именем. На переключении на другой документ начинается его новая история. Бюджет истории учитывает изменившиеся данные вместо повторного начисления общей геометрии и общих материалов за каждую точку; файловый кеш ограничен. Сохранение проекта сохраняет все объекты, даже когда изменён только один из них.
- Масса кабин оставлена доступной: она действительно присутствует в штатных script.ini, включая gravel_big с 0.52. Скорость/мощность кабин не подставляются из дорожного профиля. Дорожные коэффициенты подъёма удаляются при переходе в другой тип, неизвестные команды сохраняются.

## Общий материал основной модели и прицепа

Импорт native-модели теперь приводит только неизвестные имена её material slots к именам соответствующих native MTL slots; существующие известные имена и геометрия сохраняются, совпадение двух разных слотов после преобразования отклоняется. Это исправляет открытие bust_skd_9Tr_po1e с одной основной записью NMF и тремя записями MTL, а также именование bus_ikr_280. Исходные файлы не изменяются. PBR companion при автоматическом импорте следует за переименованными aliases.

Материалы, используемые только прицепом, доступны в общем списке «Материалы», их можно настраивать и назначать основным мешам; недостающий слот добавляется в изменяемую NMF. Выбор нового материала не затирает материал другого объекта. Локальный просмотр JOINT использует те же имена MTL. Экспорт JOINT/LODJOINT/ALPHA/CRANE/самолётных shared-винтов приводит только material table копии; части со своим MTL не затрагиваются. Отдельные внешние/анимированные узлы при этой операции остаются байт-в-байт, это не поддержка их геометрии/проигрывания.

Одинаковые повторные значения native-цвета больше не блокируют чтение. Неизменённые строки сохраняются, правка обновляет все одинаковые повторы с исходными комментариями. Разные значения одного свойства продолжают давать явную ошибку. Проверен штатный дубль AMBIENTCOLOR у MTZ в bust_skd_9Tr_po1e.

Проверка 56 штатных сочленённых машин: у 55 все реально используемые материалы частей сопоставлены; у oil_pan_movic имеется штатная ссылка на Material.003 без записи в MTL. ## Проверка native материалов 22 октября

Повторяемая проверка `dotnet run --project Packaging/MaterialAudit -c Release -- <game>/media_soviet <report.json>` охватывает 1 073 объекта и все найденные material[_N].mtl. У 124 объектов / 631 варианта определения частичные: они открываются для исправления, но это не означает готовность к экспорту. Девять MAIN остаются вне поддержанных жёстких NMF; анимации отложены.

Чтение MTL останавливается на первом терминаторе. Недостижимые блоки и ссылки сохраняются в тексте, но не загружаются и не копируются. Совместимые повторные блоки объединяются с сохранением текстур и неизвестных свойств; противоречащие определения отклоняются. Новый материал вставляется перед первым терминатором.

Имена NMF читаются как UTF-8 с сохранением исходных байтов неизменённых имён. Проверка штатных таблиц: 5 402 имени, 35 не-ASCII, недействительных UTF-8 нет. Например, koło больше не превращается в ko??o. Ограничение нового имени составляет 63 байта, а не 63 символа.

Частичный MTL больше не запрещает открыть геометрию. Неизвестные слоты не получают случайные текстуры и показываются предупреждениями; их определение можно создать в настройках материала. Неиспользованный слот NMF не требует выдуманного блока MTL. Экспорт по-прежнему проверяет реально используемые материалы.
