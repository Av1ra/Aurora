# Собственные объекты в одном проекте

21 октября 2026. Продолжать автономно до согласованного результата, не останавливаться после промежуточного комплекта. WinUI, версия 0.2. Внешние анимации и ранее отложенные идеи остаются вне текущей реализации.

## Реализовано в исходниках

- «Скрипты → Объекты комплекта»: добавить OBJ/NMF или отдельный проект, открыть другой объект, переименовать и удалить свободный объект. Каждый имеет собственные модели/LOD, варианты материалов, скрипт, груз, pivot и камеры. Настройка возможна с нуля через OBJ. Ссылки собственных секций в FAMILY/TRAINSET используют внутренний идентификатор aurora:имя; при игровом экспорте он обязательно заменяется на настоящий Workshop ID/объект.
- Один зашифрованный `.aur` содержит несколько самостоятельных документов. Общие данные хранятся по SHA-256 один раз. Сохраняются прежние пределы архива 256 MiB/2048 записей и не более 64 объектов. Старый однообъектный `.aur` открывается без преобразования владельцем. Добавление чужого однообъектного проекта меняет его ссылки на самого себя на новое локальное имя. Импорт всего другого многообъектного проекта пока отклоняется явно.
- Чтение/проверка документа вынесены из WinUI в `ProjectDocument.cs` и проверяются без окна. Оригинальный идентификатор native-объекта сохраняется отдельно. Нечитаемый дополнительный LOD можно оставить непрозрачной зависимостью проекта для дальнейшей замены; игровой экспорт по-прежнему требует корректного LOD и не выдаёт непреобразованные данные за исправленные.
- Экспорт комплекта обрабатывает все собственные объекты, их варианты материалов и настройки превью без переключения редактируемого документа. Отдельные модели, обычные/PBR-материалы, карты, звуковые INI и связанные модели переносятся в свои папки. Проверка камеры восстанавливает исходный вид после генерации изображений. Одиночный экспорт с оставшейся внутренней ссылкой проекта отклоняется.
- Переименование/удаление объекта включено в снимок истории активного документа; ссылки меняются вместе с именем. На переключении на другой документ начинается его новая история. Бюджет истории учитывает изменившиеся данные вместо повторного начисления общей геометрии и общих материалов за каждую точку; файловый кеш ограничен. Сохранение проекта сохраняет все объекты, даже когда изменён только один из них.
- Масса кабин оставлена доступной: она действительно присутствует в штатных script.ini, включая gravel_big с 0.52. Скорость/мощность кабин не подставляются из дорожного профиля. Дорожные коэффициенты подъёма удаляются при переходе в другой тип, неизвестные команды сохраняются.

Отдельная проверка создаёт голову и вагон из OBJ, сохраняет общий `.aur`, удаляет исходники, открывает каждый документ и экспортирует зарегистрированный состав с FAMILY, повторением и разворотом головы. Проверены дедупликация данных, наследование старого формата, повреждённый хеш, отсутствующая карта, непрозрачный LOD, самоссылка импортируемого объекта, запрет утечки внутренних ссылок и бюджет истории для общих данных. Сборка WinUI-модуля проходит без предупреждений.

Игровой приём нового комплекта и точное движение механизмов не объявлены проверенными. Подготовка Workshop-файлов не означает их публикацию.

## Где продолжать

- `Aurora.Core/TransportWorkspace.cs`: контейнер и дедупликация. `Aurora.Editor/ProjectDocument.cs`: проверка и извлечение отдельного документа. `EditorWorkspace.cs`: переключение/добавление/переименование; `EditorProject.cs`: захват и сохранение.
- `EditorTransportExport.cs`: экспорт всех документов и их превью без замены активных данных. `TransportPackage.cs`: объектные ссылки/регистрация, включая собственные и native-секции. `WorkspaceExportChecks.cs`: сквозная проверка.
- Следом: визуальная проверка новых окон в отдельной сборке без перехвата владельца, параметрические кузов/барабан и точное размещение частей, независимые локальные оси/кости. Не выдавать модели с неизвестными/анимированными узлами за полностью поддержанные; 2 740/2 864 NMF принимаются прежней строгой проверкой.
- У `$TOKEN_POSITION` и `$TRAINBOX` семантика пока не подтверждена. Не придумывать подписи и физику по имени команды. Существующие зависимости внешних анимаций копируются, авторинг/проигрывание отложены. Не реализовывать отвергнутые предложения лаунчера, песочницу, UI-плагин или блокировку точек.

Последний собранный и проверенный production-комплект пока относится к 202e41a (build-241bbd27565f419b8bbc47fc7536bc44); последующая настройка материалов частей и многообъектный проект в него не входят. Установленным остаётся batch 01, пока запущены приложения владельца. Следующая производственная сборка должна делаться из чистого проверенного коммита и проверяться отдельно.


## Рабочая система координат кабин

У native cabins/gravel_big MAIN используется для покупки; CRANE_STATIC — кузов ниже точки подвеса, CRANE_DYNAMIC — тележка у подвеса. Их одновременное наложение на MAIN удалено. «Скрипты → Рабочие части кабины» переключает вид на кузов и тележку с исходными смещениями. Настройка груза автоматически использует этот рабочий вид. Выбор и изменение мешей MAIN в нём отключены, включая сообщения выбора из viewport. Настройка основного pivot возвращает MAIN. Превью покупки/экспорт не включают рабочую сборку; переключатель не меняет проект или оригиналы.

Проверены обе части всех 11 native скриптов кабин с такой сборкой, включая чтение связанных NMF. Полный набор тестов проверяет 5672 типизированных записи, семь классов экспорта и многообъектный проект. WinUI-модуль: 0 предупреждений, 0 ошибок. Это размещение частей в исходном состоянии; движение подвеса и игровая физика не объявляются реализованными.

Production build-609a306fa5ca4ebca12b34d3991edeff из чистого c1f31468f9e1abbc6abbfe6f6246d02baf731125 собран и проверен на целостность adjacent ZIP и подписи двух приложений/Editor/модулей. ## Визуальная проверка параметрических осей

Для DUMPER_DECK_PIVOT / DUMPER_JOINTDECK_PIVOT и MIXER_DRUM / MIXER_JOINTDRUM размещение точки теперь показывает линию оси A/B и временный угол с шагом 0.1°. У самосвала это поперечная ось X через pivot, у барабана — две заданные точки. Проверка меняет только копии координат выбранного меша для viewport, с сохранением камеры; исходные NMF, скрипт, история изменений и экспорт не получают проверочный угол. Это диагностическая поза, а не обещание воспроизвести динамику двигателя игры. «Сбросить угол» возвращает исходный вид.

Список мешей механизмов прицепа теперь берётся из JOINT, а основной машины — из её основной модели, без смешивания имён разных LOD. Новое имя механизма проверяется на существование; прежняя неисправная native-ссылка не подменяется автоматически. В корпусе проверены 36 читаемых самосвалов/миксеров с действительной ссылкой на меш. Остальные непонятные внешние/анимированные NMF по-прежнему не пропускаются молча.

В headless Edge с настоящим WebGL2 отрисованы native кабинa для покупки, её рабочие части и бетономешалка с проверочной позой 45°/осью A/B: нет ошибок GLSL/JavaScript/GL, геометрия видима. Диагностические изображения просмотрены; тест сцены использует нейтральный материал и не доказывает текстурную/игровую идентичность. Тест Packaging/test-viewport-webgl.mjs принимает дополнительные JSON-сцены; локальные сцены и PNG лежат в ignored artifacts.
