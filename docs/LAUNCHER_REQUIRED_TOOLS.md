# Необходимые инструменты лаунчера: предложения

21 октября 2026. По запросу владельца начат разбор инструментов Aurora Launcher. Все 22 дополнительных требования редактора одобрены как важные; это отдельный список предложений для лаунчера, ещё не подтверждённый владельцем. Исходники просмотрены, приложение и игра не запускались, функциональные изменения не внесены.

## Что уже существует

App.cs, ModCatalog, ModuleRuntimeCompatibility, ModuleInstaller, WorkshopUpdates и UpdateService уже обеспечивают обнаружение подписанных модулей, проверку подписей/хешей, настройки из manifest, установку с backup/receipt и откатом при ошибке самой установки, обнаружение части конфликтов библиотек, обновления и запуск через Bootstrap. Не предлагать заново эти основы как полностью отсутствующие.

## Предлагаемый обязательный набор

1. **Состояние каждого модуля.** Различать найден, установлен, включён в конфигурации, запрошен для запуска, подтверждённо загружен и ошибка. Наличие DLL/включённый тумблер не доказывает её загрузку. Для последнего состояния понадобится явное подтверждение runtime; не выводить его по наличию процесса. Сейчас Home показывает имя и версию, запуск получает все discovered modules.
2. **Проверка готовности перед запуском.** Объединить существующие проверки файлов/подписей/конфликтов с подтверждённой совместимостью сборки игры и модулей. Результат должен назвать конкретную причину и действие. Не обещать полное распознавание конфликтов произвольных сторонних DLL. Основание: LaunchGameCore и ModuleRuntimeCompatibility.
3. **Запуск без модулей Aurora для сравнения.** Отдельный режим без передаваемых Bootstrap библиотек, с сохранением Steam-пути и конфигурации. Это не обещание абсолютно чистой игры при наличии посторонних модов. Текущий LaunchGameCore формирует список из всех найденных модулей.
4. **Восстановление модуля.** Ручная проверка и переустановка из проверенного доступного комплекта, с отчётом о заменённых файлах. Хеш-проверка и автоматическая установка уже есть при запуске; требуется самостоятельная операция, а не новая реализация копирования.
5. **Возврат к предыдущему рабочему состоянию.** Просмотр backup/receipt и обратимая операция отката выбранного обновления вместе с настройками. ModuleInstaller уже делает резервные копии и откат транзакции при ошибке; пользовательского выбора предыдущей версии в просмотренном UI нет. Учитывать общие файлы и изменения после установки.
6. **Корректное отключение и удаление.** Различать выключение эффекта в INI, исключение DLL из запуска и удаление модуля. При удалении использовать сведения об установке и владении общими файлами, сохраняя чужие изменения. Не удалять папку mods целиком.
7. **Профили настроек.** Сохранить именованный набор выбранных модулей и их конфигурации, переключить/экспортировать/импортировать. Начальные примеры — обычная игра, PBR, проверка совместимости. Профиль должен ссылаться на версии, а не переносить непроверенные DLL.
8. **Отчёт последнего запуска и пакет диагностики.** Сохранить версию/сборку Aurora и игры, список запрошенных и подтверждённых модулей, этап остановки, вывод Bootstrap и релевантные журналы. В LaunchGameCore вывод читается, но ошибка наружу сводится к Game launch failed; постоянного подробного отчёта в этом пути нет. Экспорт для пользователя — с просмотром состава и исключением секретов/личных данных.
9. **Понятные ошибки подписи и совместимости.** Вместо одного Invalid publisher signature показать источник/модуль, этап проверки и доступное действие: скачать заново, обновить комплект, выбрать правильную папку. Проверку не обходить. Основание: отображение ошибок обнаружения через status и VerifyCurrent/VerifySnapshot.
10. **Обновления по идентификатору сборки.** UpdateService.Check сейчас сравнивает Version и отклоняет version <= LauncherVersion. При сохранении версии 0.2 новая сборка 0.2 не различается этим контрактом. Добавить подписанный идентификатор сборки/ревизии, состояние скачивания и точное описание доступного обновления. Нельзя просто считать каждый иной SHA более новым: порядок обновлений должен быть задан.
11. **Подготовка обновления при работающей игре.** Проверить/скачать заранее, применять после освобождения файлов и явного действия пользователя либо ранее выбранного режима. Показать, что именно ожидает закрытия. Текущий запрет установки при запущенной игре сохраняет смысл; не завершать игру автоматически.
12. **Установка из локального проверенного комплекта.** Выбрать подписанный пакет без повторного скачивания, показать состав/сборку и применить обычные проверки. Это отдельный UI-путь, не разрешение запускать произвольные EXE. Автономная игра без сети не должна зависеть от успешности проверки обновлений.

## Приоритет

Для первого пакета предложены состояние модулей, диагностика запуска и понятные ошибки. Затем восстановление/откат и запуск без модулей Aurora. Обновления одной версии требуют отдельного изменения подписанного контракта. Оставшиеся инструменты согласовать с владельцем; это не разрешение немедленно реализовать всё перечисленное.

Версия 0.2 и WinUI сохраняются. Работа не включает публикацию Release, вмешательство в Steam Workshop downloads или управление активной игрой.
